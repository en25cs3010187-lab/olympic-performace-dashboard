Non-functional Requirements:
------------------------------------------------------------------------
Following are the non-functional requirements of the proposed solution.

NFR-1 | Usability
  The website should be simple to navigate (home page and /story page) and the
  dashboards should be readable on a laptop. The README lists a "responsive
  Flask website layout"; testing on different screen sizes is Not verified.

NFR-2 | Security
  app.py only defines two read-only routes that render templates; it does not
  accept user input or store personal data, and no login is implemented.
  The dashboards are public on Tableau Public, so only data suitable for
  public sharing should be used. Note: app.py ends with app.run(debug=True),
  which is for local use. How the live site is started on Render is
  Not verified (requirements.txt includes gunicorn). Debug mode should be off
  in production. No security testing was done.

NFR-3 | Reliability
  The site depends on three external services: the Render host, Tableau
  Public, and GitHub. If Tableau Public is unavailable, the embedded
  dashboards will not display. Reliability was Not measured.

NFR-4 | Performance
  Page load time and dashboard load time were Not measured. Because the
  dashboards are served by Tableau Public, much of the load time depends on
  Tableau and the visitor's network.

NFR-5 | Availability
  The website is reported to be live at
  https://olympic-performance-dashboard.onrender.com. Uptime, hosting plan,
  and any sleep/cold-start behaviour of the hosting plan are Not verified and
  Not measured.

NFR-6 | Scalability
  The Flask app is simple and does not keep data in memory between requests,
  so it is not complicated to run more than one copy. No load testing was done,
  so the number of concurrent visitors supported is Not measured. Adding more
  data or more dashboards would require updating Tableau extracts.
